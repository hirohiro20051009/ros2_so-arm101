## 2. 道具の設計（案）

### 2.1 構成

- **`tools/diffik_math.py`**（新規。numpy だけ。ROS なし）: 純粋な関数。`tools/servo_math.py` の `chain_from_urdf`・`jacobian`（6×5。位置・回転。先端の位置と回転行列も返す）を**再利用**する。内容: 減衰最小二乗の 1 ステップ（`dls_step`）、位置誤差・接近軸の誤差の計算、1 ステップの上限・床・`|desired − measured|` の検査、積み上げの計画。**ROS・move_group を使わない**（`/compute_fk` を呼ばない。URDF は `send_servo_twist.py` と同じく `/robot_state_publisher` の `robot_description` パラメータから取る）。
- **`tools/diffik_refine.py`**（新規。実機を動かす。**ユーザーだけが実行**）: ROS ノード。`/joint_states`（測定）、`/arm_controller/controller_state`（`desired`）を購読し、`/arm_controller/follow_joint_trajectory`（action）に送る。CLI: `--target X Y Z`（`base_link`、m）、または `--delta dx dy dz`（今の先端から）。`--dry-run`（何も送らず、計画だけ表示）。`--yes`、`--max-steps`、`--tol`。
- **誤差の出どころを差し替えられる形**: 「誤差」を返すものを 1 つの関数の形にする: `error_source(state) -> e（3 次元、base_link、m）`。
  - 今: `FkErrorSource(target)`: `e = target − FK(測った q)`（`diffik_refine.py` に内蔵）。
  - 後: `CameraErrorSource`（共通の層から、トピックまたは関数で `e` を受ける。カメラの測定時刻と、**止まっている間の値だけ**を受け付ける）。**積算・上限・床・停止は、誤差の出どころによらず同じ**。
- **記録**: 各ステップを JSON Lines に書く（`k`、時刻、`q`（tick）、`desired`、`gap = desired − q`（tick）、`p_meas`（FK）、`e`（mm）、`dq`（tick）、action の結果の status、床の最小 z）。**精度の測定（8 章）に使う**。

### 2.2 1 ステップの流れ（`so101_diffik.py` の `move_to` に、安全を足したもの）

1. **止まっていることの確認**（`servo_real_check.md` のコマンド A と同じ: 0.6 秒あけて 2 回読み、5 関節の差が 0.003 rad 以内）。
2. `desired` を読み、**前のステップに送った目標と一致する**ことを確認（一致しなければ、誰か（MoveIt など）が JTC に指令した可能性があるので**中止**）。
3. 誤差 `e` を `error_source` から得る。`‖e‖ < tol` なら成功で終了。
4. `dq = DLS(J(q), e)`、`‖dq‖ ≤ 0.05 rad`（旧 `MAX_DQ`）。
5. **送る前の検査**（4・5 章）: 床（`FK(desired + dq)` の z）、`|desired + dq − measured| ≤ W`（関節ごと。超える分は**縮める**。旧コードは送る前の値で判定していた）。
6. 1 点・`STEP_T`（2 秒）の `FollowJointTrajectory` を送る。**結果（result）を必ず待ち、status が SUCCEEDED（4）でなければ中止**（4 章）。
7. 整定を待つ（`SETTLE` 1.5 秒。7 章）。測定して、1 に戻る。最大 `max_steps`（既定 10）。

## 3. 手先の向き（接近軸）

**[事実。計算。URDF の鎖の順運動学。T の実測の関節角で、先端 (172.4, −0.4, 55.2) mm、接近軸（先端の z 軸）= (−0.043, 0.000, −0.999)（真下から 2.5° 傾き）。この FK は tf の実測と 0.2 mm 以内で一致した（accuracy 計画 2 章）]**

- 5 関節のうち、**wrist_roll は先端の位置を変えない**（先端が roll の軸の上にある）。位置に効くのは 4 関節（pan、lift、elbow、wrist_flex）で、位置 3 自由度に対して**余りが 1 自由度（≒ pitch）**。この 1 自由度で接近軸が変わる。**pan の回転は、接近軸が真下のとき傾けない**ので、**接近軸が変わるのは pitch（pan の方向を含む鉛直面内）だけ**（横方向の傾きは、関節の軸が平行なので生じない。計算でも y 方向の 5 mm で 0.10°）。
- **`so101_diffik.py` の扱い**: 位置だけの 3 次元（最小ノルム）。**姿勢は拘束しない**。

## 5. 床（Z_MIN 0.06 は旧校正の値。今の規則に合わせる）

- **旧 `Z_MIN = 0.06` は、旧校正・旧 URDF の座標**（今の床は `base_link` の z ≈ −0.0024 m、規則は下）。**そのまま使わない**。
- **今の規則（引き継ぎ）**: 先端 z ≥ **0.045 m**、T からの正味の下がり **10 mm 以内**（T の実測 z = 0.055 なので、どちらも z ≥ 0.045）、出発点からは始めない（D23。出発点の先端 z は 0.033 m < 0.045 なので、**床の規則で自動的に拒否される**。elbow の超過の問題も踏まない）。
- **指先が先端のフレームより約 6〜7 mm 下に出る**ことの扱い: 規則の 0.045 m は「フレーム」の z。**指先の下端の高さ ≒ フレームの z − 6.5 mm**（指が真下のとき）なので、**フレーム z = 0.045 のとき指先は約 38.5 mm（床の面 z = −0.0024 からは約 41 mm）**。**道具は「フレームの z」で判定し、指先の余裕は記録に出す**。接近軸が傾くと、指先のずれが変わる（傾き 3° で、指先の高さは約 1 mm 以内。計算の概算）。
- **検査の場所（旧は 3 か所）**: ① **目標の z**（`target_z ≥ 0.045`）、② **送る前の予測**: `FK(desired + dq)` の z（**旧は `FK(q + dq)`（測った q から）で、`desired ≠ q` のときに食い違った**）、③ **測った位置の z**（各ステップ）。**② は 0.048（3 mm の余裕。開く向きの手前止まりの逆（閉じる向きの行き過ぎ）の分）** を案とする。**①②③ のどれかが外れたら中止**。
- **[事実と推測]** 開く向き（z が上がる向き）の手前止まりは、**測った z が `desired` の z より低い**（T の elbow: 計算の 58.8 に対し実測 55.2）。**積み上げで `desired` が測定より高いので、床の判定は「測った z」と「`desired` の z」の両方が要る**。
- **走行中の監視**: 旧 `go()` の 0.1 秒ごとの監視（`des − meas`、測定 z）を取り込む。**ステップ（2 秒）の間も、`FK(measured)` の z < 0.045 でキャンセルではなく保持ゴール**（4 章）。

## 6. (c) の見積もり（1 ステップの dq で、摩擦の幅を何ステップで超えるか）と、(a)・(b) の見積もり（分ける）

**(c) の見積もり（ステップ方式）**

- **モデル [推測。W1 と旧校正の W3.5 の値から。関節・姿勢ごとの実測は無い]**: 摩擦の不感の幅は、開く向きの側に約 17〜27 tick（`g_o`）、閉じる向きの側に約 3 tick（`g_c`）。**不感帯の中では、`desired` を動かしても関節は動かない**。**同じ向きに続けるときは、直前の到達で `gap` が不感帯の縁にあるので、1 ステップで動き出す**。**向きを反転するとき**は、`gap` を縁から反対の縁まで動かす必要がある（幅 `g_o + g_c` ≒ **20〜30 tick**）。
- **1 ステップの `dq`（T の付近。最小ノルム DLS。計算）**と、反転のとき不感帯を超えるのに要るステップ数（幅 20〜30 tick を `dq` で割る。**関節ごと**。動かない関節が残ると誤差の方向が曲がる）:

| 先端の誤差 | lift [tick] | elbow [tick] | wrist_flex [tick] | 反転で超えるステップ数（lift / elbow / wrist_flex） |
|---|---|---|---|---|
| z 3 mm | −10.3 | −6.1 | +10.7 | 2〜3 / 4〜5 / 2〜3 |
| z 5 mm | −17.1 | −10.1 | +17.8 | 2 / 2〜3 / 2 |
| z 10 mm（`‖dq‖` を 0.05 rad にクリップ） | −20.9 | −12.3 | +21.7 | 1〜2 / 2〜3 / 1〜2 |
| x 3 mm | +2.3 | −3.2 | −9.6 | **9〜14** / 7〜10 / 3 |
| x 5 mm | +3.8 | −5.4 | −16.0 | 6〜8 / 4〜6 / 2 |
| x 10 mm（クリップ） | +7.2 | −10.1 | −30.1 | 3〜5 / 2〜3 / 1 |
| y 3 mm | pan −14.5 | — | — | 1（pan は手前止まり約 3 tick） |

- **読み方 [推測]**: 許容 3 mm（`tol`）を超える誤差（3〜10 mm）なら、**1 ステップで動き出す（同じ向き）か、反転で 2〜10 ステップ**（**1 ステップ 3.5 秒なので 7〜35 秒**）。**x の小さい補正（3 mm）は、lift・elbow の `dq` が 2〜3 tick と小さく、反転では 7〜14 ステップかかる**（`max_steps` 10〜12 を超えうる）。**その間、wrist_flex だけが動く（約 10 tick）ので、接近軸が傾く**（3 章の A）。**`stuck in play`（旧 `visit`）の検出は、この状況の検知**。**対策の案: 小さい誤差のとき、`dq` を `tol` 以下まで縮めずに、最小の 1 ステップを大きめ（例 5〜8 tick）にする（過補正のリスク。実機で決める）**。
- **ステップの上限 0.05 rad（33 tick）**は、**不感帯（20〜30 tick）を 1 ステップで超えられる大きさ**。**3 mm 未満の細かい補正が目的でなければ、1〜数ステップ**で足りる見込み。

**(a)・(b) の見積もり（連続方式。今は扱わない）**: 1 周期（約 34 ms）の積み上げが 1.41 tick（Servo の +z、入力 1.0）なら、不感帯 20〜30 tick を **12〜19 周期（約 0.4〜0.65 秒）**で超える。0.7 tick/周期（入力 0.5）なら 24〜39 周期。**連続方式は、超えた瞬間に動く（スティックスリップ）ので、`gap`（積み上げた分）の飛びが大きい**。（`docs/diffik_accumulate_plan.md` 2 章）

### 8.3 1 ステップの時間（2 秒の軌道 + 1.5 秒の整定）を短くできる余地と、危険

| 部分 | 短くする案 | 危険・条件 |
|---|---|---|
| **整定 1.5 秒** | **固定の待ちをやめ、止まったことの検知**（コマンド A: 0.6 秒あけて 2 回読み、差が 0.003 rad 以内）に置き換える。ステップが 2 + 0.6〜1.0 秒（約 2.6〜3.0 秒）に | **止まった直後のクリープ（ゆっくりした動き）で、測るのが早すぎると誤差がずれる**。**クリープは未測定**（精度の測定で 5 秒後・15 秒後を見る）。カメラ（共通の層）の測定は**露光・遅延**もあるので、ステップの終わりから測定までの待ちは共通の層の側で決める |
| **軌道 2 秒** | `dq` が小さいとき（≤ 0.02 rad）は 1 秒に（速さ ≦ 0.025 rad/s のまま） | 速くなると、**サーボの加速度（`Acceleration = 50`）・L1（39 tick/周期）・重力での垂れ**に近づく。**JTC の最短は update_rate 25 Hz で 1 点の軌道の最初の 1 更新が進まない（`servo_integration_plan.md` 3.2）ので、1 秒未満は避ける** |

### 8.4 この道具で、精度の測定も兼ねられるか

- **兼ねられる（一部）**。各ステップの記録（2.1）から、**「目標の先端に ±3 mm に追い込めるか」「何ステップかかるか」「`gap` の大きさ」「ステップごとの誤差の推移」**が取れる。**N 回（開始位置を変えて、各 3 回）の実行**で、ステップ数のばらつきと最終誤差の分布。
- **見えないもの**: **誤差は「測った関節の FK」との差**なので、**FK のモデル誤差（リンク長・校正のずれ）と、関節の量子化は見えない**。**物理の先端の位置は、定規（ユーザー）か、カメラ（共通の層）で測る**（最終位置を各 1〜2 回）。**FK の精度は T の実測と 0.2 mm 以内**（1 点だけ）。
- **保留中の精度の測定（`accuracy_measurement_plan.md`）の書き直し（「MoveIt だけで、2〜3 姿勢 × 各 3 回、先端 ±3 mm」）**とは別に、**この道具の実験が「追い込み」の精度の測定になる**。MoveIt だけの測定は、**道具の到達の起点（積算の前の到達）のばらつき**を測る位置づけ。
