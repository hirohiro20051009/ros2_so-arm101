## 1. `so101_diffik.py` の読み取り

### 1.1 読んだもの

- **読んだ**: `~/ros2_so101/test/so101_diffik.py`（144 行。全文）、`~/ros2_so101/test/readme.txt`（起動手順のメモ）、`~/ros2_so101/src/so101_ros2/so101_controller/config/so101_controllers.yaml`（`/follower` ブロックの JTC の設定の確認だけ）。
- **読んでいない（一覧。必要になれば、承認を得て読む）**: 同じディレクトリの `diffik_go.py`（多点の 1 本軌道 `go()` と再送つき `visit()`）、`diffik_path.py`（経路の計画）、`diffik_pose.py`、`contact_test.py`、`collect_cal.py`（`from so101_diffik import DiffIK` で使う。grep で import の有無だけ確認）、`so101_ik.py`（解析 IK）、`ros_bridge.py`、`cal_to_tf.py`。`so101_diffik.py` 自体は、**ローカルのモジュールを import していない**（標準・ROS・numpy のみ）。

### 1.2 何をしているか

- **[事実] 位置だけ（3 次元）の Diff-IK**。姿勢は制御しない（5 関節 → 3 自由度の最小ノルム解）。呼び出しは CLI（`so101_diffik.py X Y Z [max_steps]`、`base_link` の絶対座標 [m]）と API（`DiffIK().move_to([x, y, z])`、`record()`）。
- **入力**: 目標の先端位置（`base_link`、`gripper_frame_link`）。測定は `/follower/joint_states`（測った関節角）と `/follower/arm_controller/state`（JTC の `desired.positions` = 直前の目標）。
- **Jacobian**: **数値微分**。`MoveIt` の `/compute_fk`（`GetPositionFK`）を、**測った関節角 q** で 1 回、各関節を `EPS = 1e-4 rad` ずつずらして 5 回、合計 6 回呼ぶ（`_jac`、`:66-71`）。**move_group が必要**。
- **解き方**: 減衰最小二乗 `dq = Jᵀ (J Jᵀ + λ² I)⁻¹ e`（`LAM = 0.01`、`:109`）。`e` = 目標 − **測った関節角の FK の先端位置**（`:104-105`）。`‖dq‖ > MAX_DQ = 0.05 rad` ならノルムで縮める（`:110-111`）。
- **出力先**: **ROS の action**（`FollowJointTrajectory` → `/follower/arm_controller/follow_joint_trajectory`）。**点 1 つ、`time_from_start = STEP_T = 2.0 秒`**（`_send`、`:73-82`）。**直接シリアルは使わない**（サーボには JTC → ハードウェアの経路で届く）。
- **周期**: 1 ステップ = 送信 → `spin(STEP_T + SETTLE) = 3.5 秒`待つ（`:117`）→ 測定 → 次。最大 `max_steps`（CLI は 1〜12、API は既定 10）。**連続の制御周期は無い（ステップごと。約 0.3 Hz）**。
- **ステップごとのログ**: 誤差（mm）、実際の先端の変位、指令した dq（tick）、測った dq（tick）、lift の `desired − measured`（`:120-124`）。**指令と実測を並べて見る作り**。

### 1.3 積算の仕方（**重要。W3 の原因との対応は 2 章**）

- **[事実] 起点は「測った位置」ではなく、JTC の目標（`desired`）**: `goal = d + dq`（`:115`）。`d` は `/arm_controller/state` の `desired.positions`（`:36`、`:100`）。`q`（測った位置）は、**誤差と Jacobian を作るためだけ**に使い、**目標の起点には使わない**。
- **いつ起点を取り直すか**: **毎ステップの先頭で、`desired` を読み直す**（`:100`）。`arm_controller` は `open_loop_control: true`（旧ワークスペースも true。`so101_controllers.yaml:39`、`/follower` ブロック。**[事実] 現在の `controllers.yaml` も true**）で、`desired` は**直前に送った目標のまま**（測定に引き戻されない）ので、`d` は「前のステップの goal」と一致する **[推測。ログ未確認]**。
- **差分の積み上げ方**: `d_{k+1} = d_k + dq_k`。`dq_k` は、**「測った先端位置と目標の誤差 e_k」から毎ステップ計算**する（`e_k` は**動きが止まってから測る**）。**誤差が残る（摩擦で止まる）間は、同じ向きの dq が積み上がり、目標が測定位置から離れ続ける**。**誤差が許容（`tol` 2 mm。CLI は 5 mm）以内になると止まる**。つまり、**誤差に対する積分制御で、積分の項が JTC の目標 `d` そのもの**。
- **[推測] 「ずれ」と「移動」が区別できた理由**: **動いている最中は測らない**。送信 → 2 秒の軌道 → 1.5 秒の整定を待ってから測る（`STEP_T + SETTLE`）ので、測った誤差は**止まった状態の定常のずれ**になる。リアルタイムの連続フィードバックでは、**測った値の変化が、動いたせいか、ずれのせいかを区別できない**（遅れ・フィルタ・摩擦のすべり）。**判断の周期を、動きの時定数より長くしてある**。

## 2. W3 の結果との突き合わせ

| W3 で分かったこと | 積算方式の対応 | 見込み |
|---|---|---|
| Servo は毎周期、**測った位置**を起点に目標を作り直す（`servo_calcs.cpp:680`）。差分は +z 1.0 で 1.4〜1.7 tick/周期。**積み上がらない**（commands − measured が一定） | `so101_diffik.py` は、**目標（`desired`）を起点に積み上げる**（1.3）。誤差が残る間は、目標が測定から離れ続ける | **[推測] 解決しうる**。**積分の項（目標）が、摩擦の手前止まりの幅（17〜27 tick）を超えるまで離れる**。1.41 tick/周期（Servo、30 Hz）なら 12〜19 周期（0.4〜0.65 秒）。0.7 tick/周期（入力 0.5）なら 24〜39 周期（0.8〜1.3 秒）。**計算（ステップ応答の見積もり。実機では未確認）** |
| 1 回目の垂れ（elbow +0.0107 rad ≒ 7 tick）: 切り替えの後の最初の Servo の指令が「測定 + 差」で、JTC の目標（elbow 0.5236）と測定（0.5501）の差（17 tick）が消えた（見立て。推測） | **起点を、切り替え直前の JTC の目標（`desired`）にする**と、最初の指令は「JTC の目標」と同じで、**サーボが押していた分が消えない**。**垂れない** | **[推測]** 起点の案は 3.6 |
| 摩擦の手前止まりは、開く向き（自重に逆らう向き）で約 0.04 rad（旧校正）、T の elbow は 17 tick | 積分で超えるが、**超えた瞬間に動く（スティックスリップ）**。目標が測定から離れた分だけ**飛ぶ** | **[推測]** 離れの上限（MAX_OFFSET）を 0.04〜0.08 rad にしている（1.4）。**止まった位置のばらつきは、積分の 1 回分（`dq`）に近い**。**±3 mm（elbow で 約 0.024 rad = 16 tick）は、手前止まりの幅（17 tick）と同程度**なので、**積分の 1 回分を小さくする（`dq` を数 tick に）必要がある**（3.7） |

## 3. このリポジトリへの載せ方

### 3.0 共通の前提（どの案でも）

- **目標の起点は「切り替え直前の JTC の目標」（3.6）**。**ステップ（動かす → 止まる → 測る → 判断）の外側の判断はノードの外**（カメラ・共通の層）で、このノードは**「今の目標から、dq だけ積み上げて動かす」**を受け持つ。
- **今の構成との関係**は 3.5 の表。

### 3.1 案 (a): Servo はそのまま。Servo の出力を受けて積算する層を間に置く

```
Twist → servo_node → /servo_node の出力（Float64MultiArray。測った位置 + 差）
        → 【積算の層】 target += (出力 − 測った位置) → /forward_position_controller/commands
```
- **得**: Servo の Jacobian・特異点・衝突の減速・drift・`servo_joint_limits.yaml` の速度上限が**そのまま**使える。`use_servo`・手動の切り替え（D17）・T からの開始（D23）は変更なし。**コードは「層」だけ**（新しいノード 1 つ）。
- **失（[事実と推測] 3.2）**: ① **Servo の出力の起点は常に測定位置**で、出力は Butterworth のフィルタを通る。**層は `出力 − 測定` から差を復元するが、測定が動くと（スティックスリップ、実機で必ず起こる）フィルタの遅れが差に混ざる**（3.2）。② Servo は**層の積算した目標を知らない**（衝突・特異点の判断が測定位置の周りで行われ、積算した目標が測定から 0.04〜0.08 rad 離れていても見ない）。③ 積算の層の出力と Servo の出力が、**同じ topic に 2 つ出る**ので、Servo の出力先を別名に変える設定の変更が要る（`servo.yaml` の `command_out_topic`）。④ 層は `/joint_states` と Servo の出力を**時刻を合わせて**引く必要（ずれると差が狂う）。

### 3.2 (a) の差の復元の誤差（シミュレーション。Servo のフィルタ（係数 1.5、`y_n = 0.4(x_n + x_{n−1} + 0.5 y_{n−1})`）の計算）

- **測定が止まっているとき**: `出力 − 測定` は、最初の 3 周期で 0.4δ・0.88δ・0.98δ と立ち上がり、以後 δ。30 周期の積算は真の積算（42.3 tick。δ = 1.41）に対して **−1.06 tick（約 2.5 %）**。**実用上は問題ない**。
- **測定が 17 tick ジャンプ（スティックスリップ）したとき**: そのジャンプの周期の `出力 − 測定` は **−8.79 tick**、次の周期は −0.63、…と回復し、**30 周期の積算は 28.5 tick（真の 42.3 に対し −13.8 tick）**。**ジャンプの約 0.8 倍を、目標から引き戻す**ことになる。
- **[推測] 影響**: 目標が測定から離れて摩擦を破った（ジャンプした）直後に、**層が目標を約 0.8Δ 引き戻す**ので、**ジャンプの後の「離れ」が自動で縮む（アンチワインドアップに似る）**。ただし**意図した設計ではない**ので、**偏り（目標がずれる）の再現性は実機で測る必要がある**。**Servo の `smoothing_filter_plugin_name` を差し替えて素通しにすれば消せる**が、**プラグインのコード（C++）が要る**（今回の範囲外）。**係数（`butterworth_filter_coeff` > 1。最小に近づけると 2 点平均）を下げても、完全には消えない**。

### 3.3 案 (b): Servo を使わず、`so101_diffik.py` の方式を ROS 2 のノードとして移植する

```
外側の判断（カメラの誤差・共通の層）→ 先端の差 e [m]
   → 【積算のノード】 dq = DLS(J, e)、target += dq（上限・床・MAX_OFFSET）
        → 50 Hz で target に向けて補間して /forward_position_controller/commands
```
- **Jacobian の求め方（案）**: `/compute_fk` の数値微分（旧）ではなく、**`tools/servo_math.py` の `jacobian()`（numpy。URDF から鎖を作る。リポジトリに既にある）**を使えば、**move_group に依存せず**、1 周期の計算が軽い（`servo_math.py` は試験済み。先端の位置は T の実測と 0.2 mm 以内で一致した（accuracy 計画 2 章の順運動学と同じ式））。
- **得**: **積算の起点・上限・床・停止・タイムアウト・デッドマンを、すべて自分で設計できる**（Servo の出力の復元や遅れの問題が無い）。**`so101_diffik.py` で動いた方式をそのまま移せる**。Servo のフィルタ・Twist の単位・`scale`・`publish_period` の影響を受けない。
- **失**: **Servo の特異点・衝突の減速・drift・Servo の関節速度上限が使えない**（自前で作る。特異点は DLS の減衰 λ で緩和、自己衝突は**未対応**）。**`use_servo` と Servo 一式（servo.yaml、送信ツールなど）が不要になる**（残すが使わない。ユーザーの方針は「削除しない」）。**新しいノード（補間と上限を持つ）の実装量が (a) より大きい**。**forward controller に出すので、JTC の軌道の補間が無い**（毎周期の目標を自分で作る。ステップ（2 秒）の補間は自前）。

### 3.4 案 (c)（参考）: JTC のまま（`so101_diffik.py` を移植して、action を出す）

- **得**: **最も変更が小さい**（名前空間の削除、`move_group` への依存、ライセンス表示だけ）。**D17（手動の切り替え）・forward controller・Servo が不要**。**JTC の `desired` が積算の起点としてそのまま使える**（ユーザーが実績を持つ形）。
- **失**: ステップが粗い（2 秒の軌道と整定、約 3.5 秒周期）。**MoveIt の実行と同じ action で、排他が無い**（後から来た目標が前を置き換える。D1 の理由）。**JTC の周期（25 Hz）・L1 との関係は今と同じ**。Servo の資産（段 1〜3）を使わない。
- **位置づけ**: ユーザーの依頼は (a)・(b) の比較だが、**(c) は「最短で、実績のある形に戻る」案**として、比較の基準に入れる。

### 3.5 今の構成との関係（(a)・(b)・(c)）

| 項目 | (a) 積算の層 | (b) ノードに移植 | (c) JTC の action |
|---|---|---|---|
| ros2_control の forward controller | 使う（出力先） | 使う | **使わない** |
| **L1（1 周期の上限 39 tick）** | 守りとして働く。層の出力の 1 周期の変化を、**Servo の出力（≦ 0.34 rad）より小さく設計**する（ドライバが削るのは暴走時だけ） | 同じ（ノードが 1 周期 ≦ 0.06 rad を守る。削られる設計は避ける） | JTC の 25 Hz で、`‖dq‖ ≤ 0.05 rad / 2 秒` の補間（1 周期 ≈ 0.001 rad）で、L1 に届かない |
| **`use_servo`** | **必要**（Servo を使う） | 不要（残す） | 不要（残す） |
| **D17（手動の切り替え `switch_controllers`）** | 必要（JTC ⇄ forward）。**層は、切り替えの前の JTC の目標を取り込み、切り替えの後の最初の指令を、それにする**（3.6 の起点） | 同じ | **不要** |
| **D23（出発点からは始めない。T からの Servo）** | Servo の自己衝突の倍率（出発点で 0.015）の制約は残る | **Servo の倍率は無い**（出発点の制約は、ノード側の自己衝突・関節リミットの扱いで決める。**出発点の elbow は URDF の上限を 0.00009 rad 超えている**ので、`clamp` の設計が要る） | 出発点から動ける（JTC。Pilz は不可、OMPL 可） |
| **D18（床の制限）** | **層**で、積算した**目標**の FK が `z ≥ 0.045 m`（TCP 基準で再確認）を満たすことを検査（Servo は床を見ない） | ノードで同じ | ノードで同じ（旧 `Z_MIN` を今の値に） |
| 安全（目標と測定の差の上限） | **層**で `\|target − measured\| ≤ W` | ノードで同じ | ノードで同じ（旧 `MAX_OFFSET`） |
| 新しいコード | 層（小）+ `servo.yaml` の出力先の変更 | ノード（大）。**`tools/servo_math.py` の再利用** | ノード（小）。名前空間・FK の移植 |

### 3.6 積算の起点を「切り替え直前の JTC の目標（コマンドインターフェースの値）」にする案

- **[事実]** JTC は `on_deactivate` で position の command に**今の command の値を書き戻す**（値は変わらない）。**forward controller は指令が来るまで何も書かない**（`forward_command_controller` 2.54.1、`forward_controllers_base.cpp:106-129`。`servo_integration_plan.md` 3.1.1）。**ドライバは command を保持**し、**同じ目標を毎周期書く**（`sts3215_system.cpp:963-1003`）。**したがって、切り替えの後、層が「JTC の最後の目標」と同じ値を最初の指令にすれば、サーボには変化が無い**（垂れない）。
- **コマンドインターフェースの値の読み方 [事実と推測]**: command interface は ROS のトピックではない（ros2_control の内部）。**代わりに `/arm_controller/controller_state`（`state_publish_rate: 50`。`desired.positions` = JTC の目標。`so101_diffik.py` が読んでいる値）を、層が切り替えの前に購読して保持する**。`open_loop_control: true` の JTC は、`desired` = command interface に書いた値（**[推測]** 一致の確認はモックで）。
- **手順（案）**: ① 層は、JTC が active の間、`controller_state` の `desired` を保持（常に最新）。② 止まっていることの確認（コマンド A）→ 切り替え（`switch_controllers --strict`）。③ 切り替えの確認後、層が**最初の指令として、保持した `desired`（= T0）を publish**（Servo の出力は使わない）。④ 以後、**`target = target + 差`**（差は (a) なら復元、(b) なら dq）。⑤ **target と測定の差が W を超えたら停止**（`target` を測定に戻すか、保持）。
- **(c) は、この起点を JTC が持つ**ので、考慮が要らない。**(a)・(b) で切り替えが要る**のは、forward controller を使うため。

### 3.7 積算の設計の要点（(a)・(b) 共通。**案**）

| 項目 | 案 |
|---|---|
| 起点 | 3.6（切り替え直前の JTC の目標）。**以後、起点を取り直さない**（誤差の積分を保つ）。**取り直すのは、ユーザーの操作（リセット）または停止の後** |
| ステップ | **動かす（≦ 2 秒）→ 止まる → 外側が測る → 判断**の外側の判断は、ノードの外（`so101_diffik.py` と同じ。**リアルタイムの連続フィードバックにしない**） |
| 1 回の積み上げ | `‖dq‖ ≤ 0.05 rad`（旧）より小さく、**摩擦の幅（17〜27 tick）を一度に超えない値を数 tick 単位**にして、**止まる位置のばらつきを小さく**する（2 章の最後の行）。**値は実機で決める** |
| ワインドアップ | `\|target − measured\| ≤ W`（旧 `MAX_OFFSET` 0.08 rad。**判定は送る前に、積み上げ後の値で**行う（旧は送る前の値で判定し、最大 0.13 rad まで離れうる））。W は**開く向きの手前止まり（0.04 rad）を超える**値でないと摩擦を破れない。**W は実機で決める** |
| 速さ | 先端 ≦ 3 mm/s 程度（案）、関節 ≦ 0.05 rad/s、1 周期 ≦ L1（39 tick）の**十分内側** |
| タイムアウト・デッドマン | **入力（Twist または e）が 0.1〜0.3 秒来なければ、積算を止めて保持**。**ノードが落ちても、forward controller は最後の指令を書き続けず、ドライバが直前の目標を保持する**（トルクは切れない。腕は止まる）。**ハートビートが途絶えたら `arm_controller` に戻す**案（D17 の自動化。範囲外） |
| 停止の仕方 | 積算を止める（target を保持）／`target` を現在位置に置き直す／JTC に戻す（S3）。**旧コードに無いので追加が要る** |
| 床（D18） | **積算した target の FK** が `z ≥ 0.045 m`（TCP 基準で再確認。今の床の約束）。**積み上げ前に予測して拒否**（旧は測った q から予測していて、`d ≠ q` で食い違う） |
| NaN・範囲外 | 出さない（ドライバは NaN を破棄し、1 秒でフォルトに入る） |

## 4. 確認が必要な点（実機とモック）

| 確認 | モック | 実機 | 理由 |
|---|---|---|---|
| 起点の取り込み（`controller_state` の `desired` が、JTC の command と一致する。切り替えで `/joint_states` が 2 tick 以内） | **可** | 必要（摩擦のある状態で、垂れが消えること） | モックは摩擦が無いので、垂れない（W2 と同じ）。**実機で、W3 の 1 回目の垂れ（7 tick）が消えるか**が決め手 |

## 5. 推奨と、決めてほしいこと

- **推奨 [推測]**: **まず (c) 相当の最小の確認（`so101_diffik.py` を、名前空間だけ直して、今のリポジトリで動かす。実機はユーザーが実行）で、積算方式が今の構成（open_loop の JTC、L1、新しい校正）で効くか**を確かめる。→ 効けば、**(b)（forward controller と自前の補間）**か (a) に進む。**理由**: ① (a) は Servo のフィルタの遅れ（3.2）が差の復元を汚す。② (b) は、Servo の特異点・衝突の機能を失うが、積算の起点・上限・床・停止をすべて自分で設計でき、`so101_diffik.py` の実績をそのまま移せる。③ (c) は変更が最小。
