## 1. 読み取りの報告

### 1.1 `so101_ik.py`（旧 `~/ros2_so101/test/`。全文を読んだ）

- **解き方 [事実]**: 5 関節の**解析 IK**（XYZ + pitch + roll）。`ik(x, y, z, pitch, roll)`: ① pan: `theta1 = atan2(y − Y0, x − X0)`、`q1 = theta1 / S1`（腕全体が pan 軸を含む鉛直面内にあると仮定）。② その面内で、**手首の点** `rw = radial − AP − LT cos(pitch)`、`zw = z − Z0 − HP − LT sin(pitch)` を求め、2 リンク（L1、L2）の**余弦定理**で lift・elbow を解く（`D = (rw² + zw² − L1² − L2²) / (2 L1 L2)`。`|D| > 1 + 1e-9` なら `IKUnreachableError`）。③ elbow は **±の 2 つの枝**を両方作り、**関節の範囲内のものだけ**を残す（すべて範囲外なら `IKJointLimitError`）。④ wrist_flex は pitch から（`q4 = (pitch − D4 − S2 q2 − S3 q3) / S4`）、wrist_roll は roll から（`q5 = (roll − D5) / S5`）。
- **自由度の扱い（ラッパー）[事実]**: `orientation_adapter(quaternion, pitch, roll)` と `solve_ik(...)`。**位置 3（XYZ）+ pitch（接近軸の、鉛直面内の傾き）+ roll（wrist_roll）の 5 自由度**を指定する。**落とすのは yaw**（pan が XY の方向で決まるので独立に指定できない。クォータニオンの標準 RPY の yaw は捨てる）。**もう 1 つの自由度（接近軸の横方向の傾き）は、関節の軸が平行で作れない**（`servo_integration_plan.md` 2 章の「作れない回転の軸」と同じ）。優先順位: ① 明示された `pitch`・`roll`、② 不足分だけクォータニオンから（RPY の roll・pitch）、③ どちらも無ければ**現在の関節角の FK の pitch・roll を維持**（`solve_ik` の `current_q`）。「勝手な広範囲の pitch 探索はしない」（コメント）。
- **解の選び方 [事実]**: `select_nearest_solution`: 候補（elbow ±）から、**現在の関節角との差（−π..π に正規化した 5 関節のノルム）が最小のもの**。ユーザーの「関節の移動が小さい解を選ぶ」。
- **入出力 [事実]**: 入力は `base_link` の XYZ [m]、`current_q`（5 要素、rad）、任意で pitch・roll [rad] またはクォータニオン。出力は `q`（5 要素の `numpy` 配列、rad。ROS の関節名の順 shoulder_pan, shoulder_lift, elbow_flex, wrist_flex, wrist_roll）。`fk(q)` は `(XYZ, pitch, roll)`。エラーは `IKError`（`IKUnreachableError`・`IKJointLimitError`）。**gripper は扱わない**。
- **依存 [事実]**: `math` と `numpy` だけ（ROS・LeRobot・MoveIt に依存しない）。ほかの旧ファイル（`collect_cal.py`・`contact_test.py`）が `import so101_ik as A` で使う。
- **帰属・ライセンス [事実]**: 旧ワークスペースの git で、コミット 1b6d489（2026-11-05、作者 `hirohiro20051009`）。ファイルにライセンス・著作権の行は無い。**ユーザー自身のコード**（CLAUDE.md の「自作の解析 IK」）。外部のコードを参考にしたかは、ユーザーの記入が無かったので**未確認**（前の依頼の記入欄は空欄）。載せるときに MIT の表示を足す。
- **ガード [事実]**: `radial ≈ 0`（pan 軸の真上）での `atan2` の不安定さを避ける検査は**無い**。`within_limits` は**厳密な不等式**（許容幅なし）。**今の出発点の elbow は +1.6901 で、URDF の上限 1.69 を 0.0001 rad 超えている**ので、**出発点そのものは「範囲外」と判定される**（出発点の付近の枝は選べない）。**差分モードを出発点の近くから始めると、今の姿勢を IK で再現できない。P2 以降で扱いを決める**（P1 の `analytic_ik.within_limits` は旧コードと同じ厳密な判定のまま。出発点は roll も −0.0453（W1 の 2026-11-13 07:54 の実測。C3 直後の記録は −0.0483）で、P1 の IK は roll=0 だけなので、どちらにしても P2 まで IK には通せない）。

## 2. 差分モードの設計案

### 2.1 構成（純粋な計算とノードを分ける）

- **純粋な計算（`numpy` だけ。ROS なし）**: ① `analytic_ik`（`so101_ik.py` の移植。1.2 の定数の更新と、試験）、② `DiffMode`（状態: `target`（先端の目標 XYZ）、`pitch_ref`、`roll_ref`、`q_cmd`（前回の関節の絶対目標）。1 ステップ: 差分を足す → 検査 → 解く → 検査 → `q_cmd` を更新）。**時刻・ROS・通信を持たない**ので、単体試験だけで安全の論理（床・上限・ワインドアップ・ジャンプ）を固められる。
- **ノード**: `JointState`（測定）・`controller_state`（JTC の目標）を購読し、差分の指令（サービス・action・トピック）を受けて `DiffMode` を呼び、送り先に出す。誤差の出どころ（今は測った関節の FK。後でカメラ）は**関数の差し替え**（`error_source`）。

### 2.2 積算の起点（W3 の 1 回目の垂れの教訓）

- **積算するのは先端の目標（`target`）で、起点は「前回の目標」**。`target_k = target_{k−1} + δ_k`。**測った位置から作り直さない**（W3 の原因）。
- **モードに入るときの初期化**: **`q_cmd0` = 直前の目標（JTC の `desired` = `controller_state` の `desired.positions`）**、`target0 = FK(q_cmd0)`、`pitch_ref`・`roll_ref` = `FK(q_cmd0)` の pitch・roll。**測った位置では初期化しない**（W3 の 1 回目の垂れ: 測った位置から始めると、サーボが押していた分（`desired − measured` = 17〜27 tick）が消えて垂れる。キャンセルでも同じ。`diffik_accumulate_plan.md`・`diffik_tool_plan.md` 1.3）。
- **[事実] 往復の一致**: `IK(FK(q), current_q = q)` は `q` に戻る（`so101_ik` の FK と IK は同じモデルで、最近傍の枝を選ぶ）。**定数が古くても往復は一致する**ので、**初期化の直後の最初の指令は「今の目標のまま」になる**（動かない）。**定数の誤差（6〜11 mm）は、「絶対座標で指定した目標」が実際の位置とずれる形で効く**（相対の差分には小さい。1.2 の更新が必要な理由）。
- **`desired` が取れない（`controller_state` が無い・古い）ときは、開始しない**（測った位置にフォールバックして垂れる、という挙動を避ける。ユーザーが明示すれば測った位置で開始してもよい）。
- **MoveIt 経由のときの注意 [推測。ソースからの見立て。モックで確認]**: MoveIt の軌道の最初の点は、**MoveIt が持つ現在の状態（= 測った位置）**。`open_loop_control: true` の JTC は新しい軌道を `last_commanded_state_` から補間する（`joint_trajectory_controller.cpp:200-207`）ので、**最初の区間で目標が測った位置へ戻る**（押していた分が一度外れる）。**最後の目標は絶対値の `q_cmd` なので、積算の効果は失われない**が、**遷移の最初に垂れる可能性がある**。JTC 直接なら起点は `desired` で垂れない。

### 2.3 止まってから測る形と ±3 mm の不感帯

1. **ステップ**: 差分の指令 → 目標を送る → **動きが止まるのを待つ**（コマンド A: 0.6 秒あけて 2 回読み、差が 0.003 rad 以内。必要なら整定 1.5 秒）→ 誤差を測る → 次の差分。**連続の測定フィードバックにしない**（ユーザーの経験: ずれと移動が区別できない）。
2. **誤差の出どころ**: `e = G − p_meas`（`G` = 行きたい先の先端、`p_meas` = 測った関節の FK（**更新した定数**）。後でカメラ）。**`δ = gain × clip(e)`**（`gain` ≤ 1。0.7〜1.0 を実機で。`clip` は 1 回の上限、2.4）。
3. **±3 mm の不感帯**: `‖e‖ ≤ 3 mm` なら**指令を出さず終了（成功）**。**ヒステリシス**: 一度 3 mm 以内で終了したら、**4〜5 mm を超えるまで再起動しない**（FK の誤差・カメラの揺れで行き来しない）。**行き過ぎ（`e` の向きが反転）の回数を数え、2 回で止めて報告**（「行き過ぎと戻りのくり返し」を防ぐ。摩擦の不感帯（反転で 20〜30 tick）で、**反転すると動かないまま積み上がる**ので、反転のステップは `δ` を大きくしない）。
4. **整定の待ち**: 固定の 3.5 秒でなく「止まったことの検知」（クリープは未測定。`diffik_tool_plan.md` 8.3）。

### 2.4 上限と特異点

| 項目 | 案 |
|---|---|
| **ワインドアップ（積み上げた目標と実測の差）** | `abs(q_cmd − q_meas) ≤ W`（関節ごと）。`so101_diffik.py` の 0.08 rad の考え方: **開く向きの手前止まり（0.04 rad = 27 tick。T の elbow は 17 tick）を超える `gap` がないと摩擦を破れない**ので W は 0.04 より大きく、**最初は 0.06**、実機の `gap` の分布（記録）を見て 0.08 まで。**判定は送る前に、解いた後の `q_cmd` で**行う（旧コードは送る前の値で判定していた）。**超えたら `δ` を縮めるのではなく、「`q_cmd` を W でクリップし、`target := FK(q_cmd)` に戻す」（逆算。`target` が `q_cmd` から離れて積み上がらない）**。クリップで進まなくなったら中止（`stuck`）。 |
| **1 回の関節の変化量** | `‖q_cmd − q_cmd_prev‖ ≤ 0.05 rad`、最初の実機は 0.02 rad（先端で数 mm）。**解析 IK の解が上限を超えたら（枝の切り替え・特異点の近く）、追わずに中止**（解を縮めて送らない: 縮めると先端が目標からずれ、IK の連続性が崩れる）。 |
| **特異点の近く** | 解析 IK の特異点: ① **腕の伸びきり・折りたたみ**（`D = ±1`。elbow ≈ 0 または大きい値で `dq/dx` が発散）、② **pan 軸の真上**（`radial ≈ 0`。`atan2` が不安定。**検査が無い**: 1.1）、③ 作れない領域（`IKUnreachableError`）、④ 関節の範囲（`IKJointLimitError`）。**案**: `abs(D) > 0.98` で警告し、**それより近い目標は拒否**。**`radial < 0.05 m` は拒否**（`servo_integration_plan.md` 2.3.2: 真下で届く r は 0.05〜0.27 m）。**差分の大きさが同じでも、`dq` が上限を超えるなら中止**（上の行）。 |
| **範囲外の出発点** | 出発点の elbow は URDF の上限を 0.0001 rad 超える（1.1）。`within_limits` に**許容幅（例 1e-3 rad）**を足すか、**出発点（z = 0.033 < 0.045）は床の規則で拒否される**ので、床の規則に任せる（D23 と同じ結論）。 |

### 2.5 床・開始位置からの距離・最大回数

- **床（D18）**: **フレームの z ≥ 0.045 m**（先端 z ≥ 0.045、T からの正味の下がり 10 mm 以内）。**指先は先端のフレームより約 6〜7 mm 下に出る**（指先の下端の高さ ≒ フレーム z − 6.5 mm）。検査の場所: ① **目標 `target` の z**、② **`FK(q_cmd)` の z**（**更新した定数の FK**）、③ **測った位置の z**（各ステップ）。**案: ① ② は 0.048 m 以上**（3 mm の余裕。開く向きの手前止まりで測った z は `q_cmd` の z より低い: T で計算 58.8 に対し実測 55.2）。**①②③ のどれかが外れたら中止**（止める = `q_cmd` 保持、キャンセルしない: JTC のキャンセルは**測った位置で保持**するので垂れる。`diffik_tool_plan.md` 1.3）。
- **開始位置（モードに入った位置 `target0`）からの距離**: `‖target − target0‖ ≤ 0.03 m`（最初）、上限 0.06 m。**1 回の差分 `‖δ‖` ≤ 10 mm**（`dq` の上限が先に効く）。
- **最大回数**: 1 回のモードで最大 10 ステップ（`so101_diffik.py` と同じ。上限 12）。**モードの時間の上限**（例 120 秒）。

### 2.7 VR のトピック指令を受けるノードにする場合の最低限の守り

- **入力**: 先端の差分（`geometry_msgs/TwistStamped`、または目標姿勢 `PoseStamped`）のトピック。**クォータニオンの指令を使うなら、1.2 の注意 1（ラッパーの pitch の対応）を直し、試験する**（`ik_pitch` への変換）。
- **デッドマン**: **有効化の信号（トピックまたはボタン）が来ている間だけ**動く。**ハートビートが 0.2 秒途絶えたら停止（`q_cmd` を保持。キャンセルしない）**。
- **タイムアウト**: 指令の `stamp` が古い（> 0.1 秒）なら無視して保持。**`controller_state`・`joint_states` が古いときも停止**。
- **1 周期の上限**: 関節の変化 ≤ 0.01〜0.02 rad/周期（L1 の 0.06 rad/周期より十分内側）、先端の速さ ≤ 50 mm/s（案）。**積算の上限（W、開始位置からの距離）はそのまま**。
- **大きな飛びは追わない**: 指令の差分が上限（例 10 mm/周期）を超える、または `dq` が上限を超える（IK の枝の切り替え）ときは、**追わずに保持して「再開（re-arm）」を要求**（デッドマンを一度離して入れ直す）。**目標が実測から遠いまま積み上がらない**（ワインドアップのクリップ）。
- **起点**: モードに入るとき（有効化の立ち上がり）に 2.2 の初期化。**止まっていることの確認**（コマンド A）。
- **MoveIt 経由では遅すぎる見込み [推測。モックで遅延を測る]**: 計画 + 実行で 1 ステップ 1〜3 秒。20〜50 Hz の連続指令には使えない。**連続の送り先は JTC 直接**（**forward controller は、Servo の削除で無くなる**。代わりに **JTC の `~/joint_trajectory` トピック**（時間 ≥ 80 ms の 1 点の軌道。新しい軌道ごとに最初の 1 更新が進まない問題があるので、`update_rate` 25 → 50 の検討が要る。`servo_integration_plan.md` 3.2）か、短い action）。**VR の段階で、`DiffMode` はそのまま使い、送り先だけ差し替える**。**forward controller が必要になれば、削除の直前のコミットから戻せる**（`servo_removal_plan.md`）。

### 7.1 roll による先端のずれを IK の模型に入れる案（TCP が roll の軸から 7.9 mm 外れている）

> **【7.7 で置き換え（2026-11-13）】** この節の「段階」（P1 は roll を固定した、k を含まない模型）は、7.7 節の承認で置き換えた: **P1 の FK は roll を含める（k・ψ0・y0 を導く。D4 = 0）。IK は roll = 0 だけ（|roll| ≤ 1e-9）で、roll ≠ 0 は `ValueError`。IK で roll を扱うのは P2**。7.8 に実装の結果。

- **これは「TCP と把持の中心のずれ」（ユーザーが別に対処）とは別の、URDF の幾何の問題**（`gripper_frame_link` が roll の軸の上に無い）。
- **[事実。計算] roll を含む模型が URDF と一致する**: URDF の順運動学に対し、次の模型を 200 姿勢（roll ±2.5 rad、pan ±1.0 rad を含む）でフィットした結果、**rms 0.0056 mm、最大 0.012 mm**:
  - 面内（pan の鉛直面）: `radial = AP + L1 cos α1 + L2 cos α2 + LT cos p + k cos(ψ + ψ0)(−sin p)`、`z = Z0 + HP + L1 sin α1 + L2 sin α2 + LT sin p + k cos(ψ + ψ0) cos p`（`p` = 接近軸の pitch、`ψ = S5 q5` = roll）。
  - 面外（pan の面からの横方向）: `y' = y0 + k sin(ψ + ψ0)`、`x = X0 + radial cos θ − y' sin θ`、`y = Y0 + radial sin θ + y' cos θ`（`θ = S1 q1`）。
  - 値: **k = 7.903 mm、ψ0 = 178.79°（≒ 180°。roll = 0 で、TCP は接近軸の「−面内の垂直方向」に k だけ外れる）、y0 = −0.177 mm、LT = 159.23 mm（接近軸に沿った、wrist_flex の軸から TCP の面まで）、D4 = −0.001°（≒ 0）**。AP 0.0304、HP 0.0542、L1 0.116、L2 0.135、D2 −13.97°、D3 +2.21° は 1.2 と同じ。
- **訂正 [事実]**: **`so101_ik.py` の D4 = 0 は正しい**。roll = 0 だけに合わせたときの見かけの D4 = −2.84° と LT = 159.4 mm は、**TCP の 7.9 mm の外れが吸収されたもの**だった（1.2 の表の D4 の行を訂正した）。**ずれの原因は、D2・D3・LT の 3 つ（と、roll による TCP の外れ）**:
  - **T で `so101_ik` の先端が URDF より低い z 方向の誤差 −9.9 mm の内訳（1 つずつ `so101_ik` の値に戻した計算）**: **D3（0° ← +2.21°）−5.2 mm、LT（0.1621 ← 0.1592 m）−2.9 mm、D2（−10° ← −13.97°）−1.4 mm**、HP −0.2 mm、TCP の外れ（k = 0）−0.3 mm。x 方向は D2 −7.9 mm と TCP の外れ +7.9 mm が打ち消し合い、合計 −1.3 mm。
- **IK に入れる案（roll を決めてから、TCP の目標から手首の点を逆算する）**:
  1. **roll `ψ` を決める**（明示、または現在の roll を維持）。
  2. **横方向**: `y' = y0 + k sin(ψ + ψ0)`。**pan を、TCP の XY から `θ = atan2(y, x) − atan2(y', r')`（`r' = sqrt(x² + y² − y'²)`）で求める**（`so101_ik.py` の `atan2(dy, dx)` は `y' = 0` の特別な場合）。`r' ≥ 0` でなければ到達不可。
  3. **面内**: TCP の目標 `(r', z)` から、**接近軸の上の点**を `a = k cos(ψ + ψ0)` の外れの分だけ戻す: `(r_axis, z_axis) = (r', z) − k cos(ψ + ψ0)(−sin p, cos p)`。その軸の点から、**手首の点** = `(r_axis, z_axis) − LT (cos p, sin p)`。以降は `so101_ik.py` と同じ（余弦定理）。
  4. wrist_flex・wrist_roll は、pitch・roll から。
- **試験（colcon test。ノードなし）**: ① **roll を振った（−2.5〜2.5 rad、0.25 刻み）FK の一致**: 模型の FK と URDF の FK の差 ≤ 0.1 mm（今のフィットは 0.012 mm）。② **IK の往復**: `IK(FK(q)) = q`（1e-6 rad）、`FK(IK(p, p, ψ)) = p`（1e-9 m。同じ模型）。③ **URDF との往復**: `p = FK_urdf(q)` → `IK` → `FK_urdf` で `p` に戻る（≤ 0.1 mm）。④ **roll が 0 のとき、`y0` だけ（−0.18 mm）の横ずれ**になること。⑤ `r' < 0`・範囲外・特異点の拒否。
- **段階**: まず roll を固定した模型（k を含まない。定数 D2・D3・LT を直し、roll ≈ 0 だけ）を作り、**roll を含む模型を次の段階**にする。**roll ≠ 0 を使う前に、roll を含む模型が必要**（roll 1.0 で 7.6 mm のずれ。1.2）。

### 7.9.1 IK で roll を扱う方法（依頼 1）

- **[事実] 閉じた式で厳密に解ける。反復は要らない。** roll ψ は**入力**なので、TCP の外れ `a = k cos(ψ+ψ0)`（面内）・`b = y0 + k sin(ψ+ψ0)`（横）は**定数**。P1 の `ik_geometry` は**すでに `tcp_offsets(0.0)` で a・b を使って解いている**（7.1 の手順 2・3 の式）。**P2 の本体は `tcp_offsets(0.0)` を `tcp_offsets(roll)` に変え、`ROLL_TOLERANCE` の `ValueError` を外し、`q5 = roll / S5` を入れること**（数行）。pan の式 `θ = atan2(dy, dx) − atan2(b, r')`（`r' = sqrt(dx² + dy² − b²)`）、手首の点の逆算（`rw`・`zw`）は P1 に入っている。
- **[事実] 数値確認**: ランダム 5000 姿勢（roll は範囲いっぱい −2.74〜+2.84。符号つき radial < 0.01 m は除く）のうち 3576 姿勢で、`IK(FK(q))` が `q` に戻った（関節空間 最大 1e-12 rad、位置 最大 2e-13 mm、失敗 0）。b の範囲は roll を振って約 −6.7〜+3.1 mm（最大で |y0| + k ≈ 8.1 mm）。

2. **`DiffMode`（P4）は厳密な範囲＋入口で拒否（D）**。関節のどれかが厳密な範囲の外なら開始せず、理由（どの関節が何 rad 外か）と「T へ移動してから」を表示。**範囲外の目標を送らないこと**は、送る直前の最後の検査（厳密な範囲、床 0.048 m、非有限）と、その試験で守る。
3. **読み取り専用の道具（P3 の `ik_model_check`）だけ ε = 0.02 rad の範囲を渡す**（送らないので安全。出発点の姿勢の確認ができる）。**ε は 0.02 rad**: 出発点の elbow の超過 0.0001 rad の 200 倍の余裕。止まっているときの読み値の揺れ（1〜2 tick、約 0.003 rad）より大きい。校正のばらつき（16 tick、約 0.024 rad）までは覆わない（その場合は拒否のまま。ε を上げる根拠は今は無い）。なお、最初の案の「約 0.01 rad」は inventory の「超過は今後も 0.01 rad 程度まで変わりうる」（[推測]。旧座標との差 0.0077 rad が根拠）から取った値で、測定値ではなかったので取り下げた。
4. **床の規則との関係**: 床は目標・`FK(q_cmd)`・測定の z で別に検査する（2.5）。範囲の扱いは床に影響しない。**出発点（z = 33.9 mm）は床の規則でも拒否される**ので、(2) と二重の守り。

### 7.9.3 入力の形（依頼 3）

- **位置 3（x, y, z）＋ pitch ＋ roll の 5 自由度、yaw は捨てる、でよい。** 理由: pan が XY の方向で決まるので yaw は独立に指定できない。接近軸の横方向の傾きは、関節の軸が平行なので作れない（1.1）。
- **`so101_ik.py` との対応**: P1 の `solve_ik(x, y, z, current_q, pitch=None, roll=None)` は**旧 `solve_ik` と同じ引数名・同じ既定**（pitch・roll を省くと `current_q` の FK のものを維持）。違い: ① 定数が URDF から導いた値、② roll が使える（P2）、③ gripper を扱わない、④ **クォータニオンの引数（`orientation_adapter`）は持たない**。
- **pitch と roll の意味 [事実]**: pitch = 接近軸の鉛直面内の向き（真下 = −90°、T は −91.0°）。**roll = `S5 q5`（wrist_roll の関節角そのもの。標準の RPY の roll ではない）**。P1 の FK は roll を振って URDF の鎖と一致している（7.8）ので、**1.2 の注意 2（roll の符号の確認）は、関節の roll については解消済み**。
- **差分モードでの扱い**: `pitch_ref`・`roll_ref` はモードに入るとき `q_cmd0` の FK から取り、**以後は固定**（測定から取り直さない。2.2 と同じ理由）。
- **クォータニオンの経路は VR の段階のままでよい**。理由: 1.2 の注意 1（RPY の pitch ≠ `so101_ik` の pitch）の変換は、VR の入力の形（ヘッドセットの座標系）を決めてから試験すべき。P2 は明示的な pitch・roll だけを受ける。

### 7.9.4 枝の選び方（依頼 4）

- **[事実] roll を含めても、順位は変わらない。** 2 つの枝で q1 と q5 は同じ（7.9.1）。ノルムの差は q2・q3・q4 だけで決まるので、**「関節の移動が小さい解」の定義は、P1 のまま（5 関節の角度差を (−π, π] に直した 2-ノルム、重みなし）でよい**。roll の項は両枝に同じ量が加わるだけ。
- **基準は `q_cmd_prev`（前回の関節の絶対目標）**。**測った位置ではない**（2.2 の W3 の教訓と同じ。測定は摩擦・重力で目標から外れている）。`solve_ik` の `current_q` に `q_cmd_prev` を渡す。
- **範囲外の候補を先に除き、残りから選ぶ（P1 と同じ）**。**近い枝が範囲外で、遠い枝だけ範囲内のときは、遠い枝へ飛ばない**: DiffMode の 1 回の関節変化の上限（0.05 rad、最初は 0.02。2.4）で**枝の切り替えを検出して中止**する（追わない。`stuck`）。
- **重みを付けない理由**: 付けると手首の小さな動き（wrist_flex・roll）を安く見積もる向きに枝が変わる根拠を、実機の測定なしに決められない。必要になったら P5 の実機の記録で決める。

### 7.9.6 P3 との順番（依頼 6）

- **推奨: P2 → P3 → P4**。理由: P2 の roll の模型は URDF の鎖（自前）と比べているだけで、**独立な基準（MoveIt の `/compute_fk`）との一致は P3 で初めて分かる**。P4（DiffMode）は roll を含む IK に依存するので、P3 の確認の後に進めると手戻りが小さい。
- **P3 の中の順**: ① fixture（`--record-fixture`。モックの `move_group`、許可を得て Claude が実行）と、それを読む試験 → ② `tools/ik_model_check.py` の表示部分。**① は、ユーザーが実機を使っていない状態が要る**（モックの起動）。
- **実機をユーザーが使い続けている間の代替**: モックもビルドも要らない P4（純粋な計算）の設計・試験を先に進められる。ただし **P4 の roll の試験は、P3 の fixture で独立な基準が取れてから確定**する。
